# 行動適用モデル

状況認識 → 関連情報の取得 → 適用規則の特定 → 行動候補の生成 → 権限・安全性・優先順位の確認 → 行動選択 → 実行または保留 → 結果の記録と評価。

この流れは今回の設計モデルであり、実行エンジンや自律意思の実装ではない。実際に観測できたStage 1のGitHub提出・検証経路とは分ける。成功した保存やCIから、全会話の規則遵守・自発性・心理効果・長期安定性を推定しない。

## 六つの事例

| ID | 状況 | 判断の分岐と保留条件 | 結果に必要な証拠 |
| --- | --- | --- | --- |
| CASE-001 | 実装依頼 | 対象・成果・許可・公開範囲を固定。許可内の最小差分を進め、規則改訂や公開範囲拡大は保留 | main/HEAD、差分、検査、同HEADレビュー、CIを個別に記録 |
| CASE-002 | 独立レビューで不具合 | 同HEADと再現条件で確認。誤りなら許可内で修正。反証は原証拠で説明 | 元の失敗、修正差分、同条件再検証、独立再確認 |
| CASE-003 | 規則衝突 | 原文・版・承認範囲を照合。未確定の序列を作らず、衝突する操作のみ保留 | 対立する解釈、既存決定、不足証拠、利用者判断 |
| CASE-004 | 曖昧な指示 | 既存資料で解ける点を調べる。対象・結果・公開等を変える一点は確認 | 質問、応答、影響する操作と独立に進めた範囲 |
| CASE-005 | 余暇の発生 | 未完了任務と現在有効な許可、期間・資源・発言条件を確認。非活動も候補。過去試験を再開しない | 状態取得範囲、時刻、選択・非活動・不明・欠測の区別 |
| CASE-006 | 自発的な研究提案 | 既存活動と重複を調べ、問い・仮説・反例・必要証拠を提示。提案から実験権限を導かない | 未承認の提案記録、採用判断、着手との区別 |

[機械可読の各段階](public-relations.json) に7以上の判断段階を記載。6件すべてDESIGN_ONLY。これは試験で観測した6件の実行実績ではない。

## 観測済みの機能と構想の分離

[Stage 1 PR #3](https://github.com/tetsujisugimori-coder/Hachibei-Lab/pull/3) と[固定HEADのCI](https://github.com/tetsujisugimori-coder/Hachibei-Lab/actions/runs/42720040287)には、その提出・検査の公開記録がある。この事実は「特定成果を提出・検証できた」範囲。上記8段階が常時自動実装されている証拠にはならない。

本工程で新しいスケジュール、実際の余暇実験、会話介入、哲学原理の自動適用、設定切替は行わない。今後の実験には、観測対象、実行許可、対照条件、中断・終了・資源制約、独立検証を別に定める必要がある。
