# 採点側専用照合設計

採点データとB0送信用データは別schema/アクセス領域。check.pyのscoring_a0/a1を持つ合成objectは採点側専用で、B0実行入力へ一切送信しない。公開fixtureは無害な合成文字列だけ。将来A0/A1は別途認可後に正解管理担当だけが保持し、監査は許可範囲内で行う。

A0/A1それぞれについて全byte一致、連続10 Unicode code point以上の部分一致候補、人手による言換え/意味/偶然/一般知識/誤検出/判定不能を記録。A0=不一致でもA1一致ならSTOP_REVIEW。機械的部分一致は意味や固有性の認証ではない。人手は比較箇所・理由・担当・時刻・版を記載し、意味的審査未完はUNKNOWN/REVIEW_PENDINGでB1不可。機械未検出だけで漏出なしPASSにしない。

check.pyのPASS/NO_TRIGGER_IN_SCOPEは合成票の限定整合で、B0成功や情報遮断の証明ではない。実際の人手の判断品質は今回NOT_TESTED。完全/部分/意味疑いはSTOP_REVIEW、疑い解消でも自動再開なし。一般知識・偶然一致と決め付けない。

B1は凍結A1との再述/末尾追加を採点。正当に提供した本文の再述はB0秘密再現として止めない。B0/B1の課題・原文・難度・初期状態が異なるので一致率の差で能力/因果を順位付けしない。

実装は最初の停止兆候で停止結果を返す。A0/A1両方の全文採点帳を出力する実サービスadapterではない。停止後の審査では両対象の個別欄を残す。

## 2026-11-18 追加レビューによる限定PASS契約の補訂

B0 の PASS/NO_TRIGGER_IN_SCOPE は A0/A1 の一致疑義がなく、合成実行主体が識別され、B0 の封印 (`b0_sealed=true`)、保存後再取得 (`b0_custody=PASS`)、総合審査 (`b0_review=NO_SUSPICION_IN_SCOPE`) がすべて宣言上成立した場合に限定する。保全・審査未了は BLOCKED とし、成功扱いしない。これは合成票の整合性のPASSであり、実原票の真正性・実験開始許可を意味しない。

B1 の TASK_MATCH 判定では、総合 `b0_review` に加えて `human_a0`/`human_a1` の個別審査状態を独立確認する。いずれか SUSPECTED は STOP_REVIEW、PENDING/UNKNOWN 等の未完了状態は BLOCKED。総合審査だけがクリアでも個別状態との矛盾を無視しない。既存のB0/B1別スレッド条件と、B1内での改訂許容は維持する。

## 空白のみの応答に関する追加局所補訂（2026-11-19）

応答 `output` は型が文字列であることを検査した後に、`output.strip()` の結果が空なら `MISSING/OUTPUT_MISSING` とする。元の `output` の原byte・改行・Unicodeは変更せず、判定時だけ空白のみかを評価する。空白以外を含む応答は従前どおり原文のまま照合し、B1の完全一致を緩和しない。B0とB1の両条件で同一契約を使用し、合成判定の `permit=false`・実験開始 `BLOCKED` を保持する。
